# Vanilla Sky 放票监测 · 云端兜底

按格鲁吉亚的作息查 Vanilla Sky 十月梅斯蒂亚航线，有票就推 Bark。
本机脚本是主力（45–150 秒一轮），这里只是家里断电断网、电脑关机时的最后一道保险。

## 节奏

| 档 | 频率 | UTC | 格鲁吉亚当地 | 次数/天 |
|---|---|---|---|---|
| 密 | 每 15 分钟 | 05:00–15:59 | 09:00–19:59（上班时间） | 44 |
| 疏 | 每小时 | 16:00–04:59 | 下班和夜里 | 13 |

一天 57 次。排班上架只可能发生在当地上班时间，所以密档压在那一段，
其余时段只求「别断了」。兜底没必要跑得比主力还勤，对人家的订票站也客气些。

行程最后一天（`watch-once.ps1` 里的 `$TripLastDate`）过后，脚本会直接退出不做任何查询。
定时任务本身没法自己关掉，所以到时候还是要手动 Disable，见下面「停掉」。

## 部署（十分钟）

1. 在 GitHub 上建一个**公开**仓库，随便叫什么，比如 `vs-watch`。

   **公开仓库的 Actions 分钟数不限量**，怎么跑都不花钱，Bark key 走 Secrets 也读不到。
   非要用私有仓库的话，免费额度是每月 2000 分钟，按现在这个节奏一个月约 2600 分钟会超，
   得把密档也改成每小时（`- cron: '0 * * * *'` 一条搞定，约 1000 分钟/月）。

2. 往仓库里放三个文件，**只放这三个**：

   ```
   vs-core.ps1                              <- 从上级目录复制过来
   watch-once.ps1
   .github/workflows/vanillasky-watch.yml
   ```

   `.gitignore` 已经把乘客信息、日志、本机脚本全挡在外面了。
   推之前自己再扫一眼 `git status`，确认没有任何带姓名护照号的文件。

3. 仓库 → Settings → Secrets and variables → Actions → New repository secret
   Name 填 `BARK_KEY`，Value 填你的 Bark key —— **`https://api.day.app/XXXX/` 中间那段**，
   不是整条 URL。整条粘进去脚本也认（会自动拆），但填 key 最干净。

4. Actions 标签页 → 左边选「Vanilla Sky 放票监测」→ Run workflow 手动跑一次。
   日志里应该看到六行查询结果。

5. 验证推送真的能到手机：把 `watch-once.ps1` 里 `$Targets` 临时改成一个当前有票的班次
   （比如 `Dep='7'; Arr='4'; Date='08/24/2026'`），提交、手动触发、确认手机响。
   验完改回来。

## 停掉

抢到票之后：Actions → 选这个 workflow → 右上角 `⋯` → Disable workflow。
或者直接把仓库删了。

## 三个注意事项

- **cron 会延迟。** GitHub 的定时任务在高峰期经常晚几分钟甚至更久，
  所以它只能当兜底。真正的快档在你自己电脑上。
- **命中后会一直推。** 每轮都会重复一次，直到你手动停掉 workflow。
  这是故意的 —— 云端是最后一道保险，宁可吵也不能漏。
- **它不知道你已经抢到了。** 本机那份可以用 `-Done 去程` 标记，云端读不到那个文件。
  所以抢到票之后必须手动去 Disable workflow，否则它会继续查、继续推。
